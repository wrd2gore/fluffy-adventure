دليل تشغيل منصة رصد الغياب المدرسي

المنصة تعمل على Cloudflare (الموقع وقاعدة البيانات) وFirebase Authentication (حسابات الدخول). كل ما في هذا الدليل يعمل بالخطط المجانية.

تنبيه مهم: لا تدفع ولا تشترك في أي شيء. في Firebase اختر خطة Spark (المجانية) ولا تضغط «Upgrade» أو «Blaze» ولا تفعّل «Identity Platform». في Cloudflare اختر Free. لا تحتاج بطاقة بنكية في أي خطوة من هذا الدليل. إن طُلبت منك بطاقة، توقف ولا تكمل.

0) ما الذي تحتاجه

  • برنامج Node.js (النسخة LTS) من nodejs.org — تثبيت عادي.
  • حساب Google (لـ Firebase) وحساب Cloudflare مجاني (البريد الإلكتروني فقط).
  • مجلد المشروع: site (الواجهة) وserver (الخادم وقاعدة البيانات) وguide (هذا الدليل).

1) إعداد Firebase (حسابات الدخول)

  1. افتح console.firebase.google.com ← Create a project ← أي اسم (مثلاً school-attendance) ← عطّل Google Analytics ← Create.
  2. من القائمة: Build ← Authentication ← Get started ← Sign-in method ← فعّل Email/Password فقط (الخيار الأول، وليس Email link) ← Save.
  3. حساب الإدارة: Authentication ← Users ← Add user ← البريد admin@school.example (بريد شكلي لا تحتاج أن يكون حقيقياً) وكلمة مرور قوية من اختيارك (12 حرفاً فأكثر). بعد إنشائه انسخ قيمة User UID (نص طويل) — ستحتاجه في الخطوة 3.
  4. مفتاح الواجهة: ⚙ Project settings ← General ← Web API Key (يبدأ بـ AIza…) انسخه.
  5. حساب الخدمة: ⚙ Project settings ← Service accounts ← Generate new private key ← يُنزَّل ملف JSON. هذا الملف سرّي جداً: لا ترسله لأحد ولا ترفعه لأي مكان، وستحذفه بعد الخطوة 3.
  6. تقييد المفتاح (موصى به): افتح console.cloud.google.com ← APIs & Services ← Credentials ← مفتاح Browser key ← API restrictions ← Restrict key ← Identity Toolkit API فقط ← Save. (لا تضع قيد HTTP referrers لأن الاتصال يأتي من خوادم Cloudflare.)

2) إعداد Cloudflare (الموقع وقاعدة البيانات)

افتح نافذة الأوامر (Command Prompt أو PowerShell) داخل مجلد server:

npm install
npx wrangler login
npx wrangler d1 create school-db
  1. أمر login يفتح المتصفح لتسجيل الدخول إلى Cloudflare والموافقة.
  2. أمر d1 create يطبع database_id. انسخه وضعه في ملف wrangler.toml مكان النص العربي في سطر database_id.
  3. أنشئ جداول القاعدة: 
    npm run db:remote

3) إضافة الأسرار (لا تُكتب في أي ملف)

npx wrangler secret put FIREBASE_API_KEY
npx wrangler secret put ADMIN_UIDS
type مسار-ملف-الخدمة.json | npx wrangler secret put FIREBASE_SERVICE_ACCOUNT
  • الأول: الصق Web API Key. الثاني: الصق User UID الخاص بحساب الإدارة (يمكن إضافة أكثر من مدير مفصولين بفاصلة).
  • الثالث: يرسل محتوى ملف JSON كاملاً كسرّ. إن ظهر سؤال عن إنشاء Worker جديد أجب Y.
  • بعد نجاحه احذف ملف JSON من جهازك.

4) النشر

npm run deploy

سيظهر رابط مثل https://school-attendance.اسم-حسابك.workers.dev — هذا رابط الموقع. جرّب فتحه من الجوال.

5) أول استخدام

  1. افتح الموقع ← لوحة الإدارة ← ادخل باسم المستخدم admin وكلمة المرور التي اخترتها في Firebase (لا تحتاج كتابة بريد).
  2. تبويب المعلمون ← الصق قائمة الأسماء (الملف server/teachers.txt فيه الـ47 اسماً جاهزة) ← إنشاء الحسابات. ينشئ لكل معلم اسم مستخدم (t01، t02 …) وكلمة مرور عشوائية.
  3. اطبع البطاقات أو نزّل ملف CSV فوراً: كلمات المرور تظهر هذه المرة فقط ولا تُخزَّن في أي مكان. سلّم كل معلم بطاقته. المعلم يدخل بكتابة اسمه (مثل «احمد اسلامية»، ولا يلزم كلمة «الأستاذ») وكلمة المرور من البطاقة، ثم يُطلب منه فوراً اختيار كلمة مرور خاصة به. وبعد ذلك يستطيع تغييرها متى شاء من زر المفتاح أعلى الصفحة.
  4. تبويب الصفوف والطلاب ← أضف كل صف أساسي (رقم الطالب - اسم الطالب في كل سطر)، ثم المواد المتنقلة بنفس أرقام الطلاب لتُربط بصفوفهم تلقائياً.
  5. تبويب الإعدادات: عدّل اسم المدرسة واسم المدير ولائحة الإجراءات.
  6. نسيَ معلم كلمة مروره؟ المعلمون ← كلمة مرور جديدة (تظهر لك مرة واحدة).

6) حماية إضافية مجانية (موصى بها)

أ) Cloudflare Turnstile (بديل CAPTCHA مجاني)

  1. لوحة Cloudflare ← Turnstile ← Add widget ← أضف نطاق موقعك (مثلاً school-attendance.اسم-حسابك.workers.dev) ← Managed.
  2. ضع Site Key في wrangler.toml مكان TURNSTILE_SITE_KEY، وأضف Secret Key بالأمر: npx wrangler secret put TURNSTILE_SECRET ثم npm run deploy.

ب) تحديد معدل محاولات الدخول من Cloudflare

الموقع يمنع بنفسه التخمين (5 محاولات خاطئة لكل مستخدم و10 لكل عنوان خلال 10 دقائق). يمكنك إضافة طبقة ثانية من لوحة Cloudflare ← Security ← WAF ← Rate limiting rules (الخطة المجانية تسمح بقاعدة واحدة) على المسار /api/login. هذه الخطوة اختيارية، وخيارات اللوحة تتغير أحياناً.

7) تجربة على جهازك قبل النشر (موصى به، دون أي حساب)

مهم: لا تفتح index.html بالنقر المزدوج. الموقع يحتاج الخادم، وبدونه لن يعمل الدخول (ستظهر رسالة «الخادم غير متصل»). للتجربة استخدم الطريقة التالية.
  1. ثبّت Node.js (الخطوة 0) مرة واحدة.
  2. افتح مجلد server وانقر مرتين على start-local.bat. (أو من نافذة الأوامر: node local-setup.mjs.)
  3. ينتظر دقيقة في أول مرة، ثم يفتح المتصفح على http://localhost:8787 وقد جهّز كل شيء: قاعدة بيانات تجريبية وحسابات الـ47 معلماً.
  4. كلمات مرور المعلمين المؤقتة في الملف server/teachers-login.csv (يُفتح بـ Excel). المعلم يكتب اسمه + كلمة المرور.
  5. الإدارة: اسم المستخدم admin وكلمة المرور من الملف server/.dev.vars (السطر DEV_ADMIN_PASSWORD).

هذا الوضع للتجربة فقط: بيانات وهمية على جهازك، لا يتصل بـ Firebase، ولا يمكن تفعيله على الموقع المنشور. اختبارات الأمان: npm test (تحتاج Node 22 أو أحدث).

8) النسخ الاحتياطي

npx wrangler d1 export school-db --remote --output=backup.sql

شغّله مرة كل أسبوع أو شهر واحفظ الملف في مكان آمن (يحتوي أسماء الطلاب فلا تنشره). Cloudflare تحتفظ أيضاً بخاصية الاسترجاع الزمني (Time Travel) لمدة محدودة تختلف حسب الخطة؛ راجع صفحة D1 في وثائق Cloudflare لمعرفة المدة الحالية.

الميزات (مطابقة للنموذج الذي أرسلته)

  • بوابة المعلمين: دخول بحساب خاص لكل معلم، رصد (حاضر/غائب/متأخر + عذر) لحصة وصف وتاريخ، التقرير اليومي للغائبين، إحصائيات ونسب المعلمين الأسبوعية، مزامنة تلقائية إن رصد معلم آخر الحصة نفسها.
  • لوحة الإدارة: التقرير الشهري (5 أيام فأكثر) مع لائحة الإجراءات الملوّنة وحذف تواريخ الغياب، إضافة صف أساسي أو مادة متنقلة، إضافة طلاب لصف قائم، حذف الصفوف والطلاب، إدارة المعلمين (إضافة جماعية، بحث، كلمة مرور جديدة، حذف)، حذف سجل حصة، تعديل بيانات المدرسة واللائحة، سجل عمليات.
  • الفئات: «الصفوف الأساسية» و«المواد المتنقلة»؛ ويرتبط الطالب بالاثنين برقمه فتُحسب غيابات المادة المتنقلة على صفه الأساسي.

لماذا لا يمكن اختراقه بالطرق الشائعة

الخطرما يمنعه
وصول الإنترنت إلى قاعدة البياناتقاعدة D1 ليس لها أي عنوان عام. لا يصل إليها إلا worker.js عبر ربط داخلي. المتصفح لا يتصل بالقاعدة ولا بـ Firebase أبداً، بل بالخادم فقط.
حقن SQLكل استعلام نصه ثابت وقيمه تُمرَّر عبر bind()، والإدخالات تُفحص بصيغ صارمة (أرقام وتواريخ وقوائم محددة). اختبار آلي يفحص الكود ويرفض أي دمج نصوص في SQL، واختبارات تجرّب حمولات حقن حقيقية.
XSS (حقن سكربتات)الواجهة لا تستخدم HTML خام إطلاقاً (نصوص فقط)، وسياسة CSP صارمة تمنع أي سكربت أو نمط مضمّن، وهذا مفحوص باختبار.
دخول معلم للوحة الإدارةالصلاحية تُفحص في الخادم لكل طلب (وليس في الواجهة فقط): كل مسار /api/admin/* يرفض غير الإدارة بـ403، واختبار يجرّب كل المسارات بحساب معلم. بوابة المعلم لا تقبل حساب الإدارة والعكس.
سرقة الجلسة / CSRFملف ارتباط HttpOnly وSecure وSameSite=Strict، والقاعدة تحفظ بصمة SHA-256 فقط، وتُفحص ترويسة Origin لكل طلب تغيير.
تخمين كلمات المرورحد للمحاولات لكل مستخدم وعنوان، وTurnstile اختياري، وحماية Firebase الداخلية.
تسريب الأسرارمفتاح Firebase وحساب الخدمة أسرار في Cloudflare فقط ولا تُكتب في الملفات ولا تصل للمتصفح.

10) حدود يجب أن تعرفها بصدق

  • أجريت الاختبارات الكاملة محلياً (29 اختباراً + تشغيل الموقع في محاكي Cloudflare وتجربة المتصفح)، لكن لم يُختبر الاتصال بـ Firebase وCloudflare الحقيقيين لأن ذلك يحتاج حساباتك. شكل طلبات Firebase مطابق للوثائق واختُبر بطلبات وهمية، فإن ظهر خطأ عند أول تشغيل فهو غالباً في الإعداد (راجع القسم 11).
  • الحدود المجانية لدى Cloudflare وFirebase كبيرة لمدرسة واحدة بكثير، لكنها قد تتغير؛ راجع صفحات الأسعار الحالية قبل الاعتماد عليها.
  • حسابات المعلمين تستخدم بريداً وهمياً (t01@school.example) داخل Firebase، لذلك لا توجد خاصية «نسيت كلمة المرور» بالبريد؛ الإدارة تعيد تعيينها.
  • المعلم لا يعدّل رصداً بعد حفظه (لمنع التلاعب)؛ تحذف الإدارة سجل الحصة فيعيد المعلم رصدها.
  • يظهر التقرير اليومي والإحصائيات الأسبوعية في بوابة المعلمين كما في النموذج الذي أرسلته (قراءة فقط). أما التقرير الشهري والإدارة فللإدارة وحدها.
  • يستطيع المعلم تسجيل غياب حتى 14 يوماً سابقة، ولا يستطيع تسجيل يوم عطلة (الجمعة والسبت) أو تاريخ مستقبلي. تغيير ذلك من أعلى worker.js (قسم CONFIG).

11) حلّ المشكلات

المشكلةالحل
«بيانات الدخول غير صحيحة» للإدارةتأكد أن مستخدم Firebase بريده بالضبط admin@school.example، وأن Email/Password مفعّل، وأن كلمة المرور صحيحة.
«الخادم غير متصل»الصفحة فُتحت بلا خادم. استخدم start-local.bat أو الرابط المنشور.
«يوجد أكثر من معلم بهذا الاسم»على المعلم كتابة اسمه كاملاً أو اسم المستخدم المطبوع في بطاقته (t01 …).
«هذا الحساب لا يملك صلاحية الإدارة»قيمة ADMIN_UIDS لا تطابق User UID في Firebase. أعد تنفيذ secret put ADMIN_UIDS ثم npm run deploy.
«إعداد Firebase غير مكتمل» أو خطأ 500سرّ FIREBASE_SERVICE_ACCOUNT لم يُلصق كاملاً. أعد وضعه بالأمر في الخطوة 3.
«تعذّر إنشاء حساب» عند إضافة المعلمينتأكد من تفعيل Email/Password، ومن أن حساب الخدمة من نفس مشروع Firebase. وإن رفض Firebase النطاق الوهمي فغيّر EMAIL_DOMAIN في أعلى worker.js إلى أي نطاق صالح الشكل ثم انشر من جديد.
